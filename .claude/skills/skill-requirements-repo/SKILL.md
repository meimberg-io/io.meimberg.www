## Interfaces

What a call binds before the run starts, and what the run hands back. A required input that is not bound stops the run.

- `requirements-repo` (input, optional, type not declared): The docs/requirements/ tree of a project that is being written, extended or read; bootstrapped with the kit, README registry, contexts/_template/, shared/entities/ and glossary.md.
- `target-project` (input, optional, type not declared): The repository of the legacy application in which docs/requirements/ is to be created. Required by the bootstrap part.
- `legacy-module-map` (input, optional, type not declared): The top-level business modules of the legacy application, used to seed the context registry. Required by the bootstrap part.
- `legacy-source` (input, optional, type not declared): Source code of the legacy application — package tree, DB schema, JPA or Force-DB and domain classes, services, validators, reports and SQL, i18n, templates, scheduler configuration, tests.
- `business-ownership` (input, optional, type not declared): Who owns which business area (teams, people responsible), as a cohesion signal the code does not show.
- `chosen-context` (input, optional, type not declared): The bounded context an extraction part works on, by its CTX code from the registry, with contexts/<ctx>/ already created.
- `domain-expert` (input, optional, type not declared): A person who can define terms whose meaning the code does not reveal.
- `context-glossary` (input, optional, type not declared): The glossary terms of the context; they seed entity names, and the ones marked as derived form the calculation work list.
- `context-entities` (input, optional, type not declared): The entity files of the context, whose attributes the formula inputs point to.
- `context-artifacts` (input, optional, type not declared): The entity files and the glossary already produced for the context, so that rule references point to existing IDs.
- `requirements-corpus` (input, optional, type not declared): Paths of the documents of a corpus to gate — use cases, functional specification sections, an extracted requirements tree.
- `next-artifact` (input, optional, type not declared): What the corpus is to carry next — data model, concept, tickets or API. Required by the corpus review part.
- `external-reference` (input, optional, type not declared): A reference model of the domain to check completeness against, if one is known.
- `question-sink` (input, optional, type not declared): Where follow-up questions land — open-points register, question catalogue or ticket.
