## Interfaces

What a call binds before the run starts, and what the run hands back. A required input that is not bound stops the run.

- `current-worktree` (input, optional, type not declared): The linked git worktree this session runs in, whose work is finished, committed and verified when it is finished or reintegrated.
- `base-branch` (input, optional, type not declared): The branch a worktree branches from and its commits are merged or cherry-picked back onto, usually main.
- `repository` (input, optional, type not declared): The git repository whose worktrees are audited, entered from its main worktree or any linked one.
- `adopting-project` (input, optional, type not declared): The repository whose worktrees should get isolated resources; in Claude Code optionally with the worktree hooks in its own settings.
- `resource-manifest` (input, optional, type not declared): The project's .leafcutter/worktree-resources.json that says which ports and which database schema to isolate.
- `project-test-setup` (input, optional, type not declared): The project's test and dev setup, with its fixed ports, its database provisioning and its validate command.
- `personal-shell` (input, optional, type not declared): The developer's own shell configuration (~/.bashrc or ~/.zshrc) the launcher function goes into.
- `ticket-id` (input, optional, type not declared): The ticket to implement through the launcher, for example T-NNNN for Cube.
